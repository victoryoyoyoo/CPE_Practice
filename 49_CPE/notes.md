# CPE 49 題筆記

目標:7 題對 5 題就好,不用每個雷都排。標 ⭐ 的是很多題都會用到、務必秒懂的東西;標「進階」的是比較少見但遇到就是送分或送命的技巧。

## 讀取輸入的套路

- ⭐ **讀到 EOF 為止**:`while(cin >> a >> b)`,不用先讀筆數。(100, 10055, 10071, 11150)
- ⭐ **讀到指定終止值為止**:`while(cin >> N && N != 0)`,終止值通常題目會講(0、"0"字串、負數)。(11332, 10929, 10931, 11461 用 `a!=0||b!=0` 兩個變數版)
- **`cin >>` 混 `getline` 會出事**:`cin >> a` 讀完數字後,換行符還卡在流裡沒被吃掉,直接接 `getline` 會讀到空字串。
  - 舊寫法:`cin.ignore(10000, '\n')` 吃到下一個換行為止(10008, 10226 用這招)
  - ⭐ 更穩的寫法:`getline(cin >> ws, line)`,`ws` 會把所有連續空白/換行(不管 `\n` 還是 `\r\n`)一次清光,不用猜要 ignore 幾個字元。(10268 踩過這個雷,Windows 的 `\r\n` 用 `cin.ignore()` 只吃一個字元會出包)
- **一行裡有不定數量的數字**:先 `getline` 抓整行字串,再包成 `stringstream ss(line)`,用 `while(ss >> x)` 拆,因為 `ss` 的範圍被鎖在這一行,不會吃到下一行。(10268)
- **逐字元讀取**,連空白、換行都要原樣印出的題目用 `cin.get(c)`,不能用 `cin >>`(`>>` 會跳過空白)。(272 TeX Quotes, 10222 鍵盤解碼)
- **一行代表一筆資料,空行代表分段結束**:`while(getline(cin, name) && name != "")`。(10226 樹種統計)

## 字串處理

- 字元判斷/轉換:`isalpha(c)`、`toupper(c)`、`tolower(c)`。(10008, 10222)
- `string::find(c)` 找字元在字串中的位置,找不到回傳 `string::npos`,要判斷才不會誤用。(10222 鍵盤位移解碼:建一個代表鍵盤排列的字串,`find` 找目前字元的 index,位移幾格去對應排列裡的其他字元)
- **兩字串找共同字母**(進階但很常考的套路):把兩個字串各自 `sort()`,變成雙指標從頭掃,相等就收一個、指標各自 +1,不相等就把比較小的那個指標往前移。這是雙指標(two pointers)在字串題的經典應用。(10252)
- `reverse(s.begin(), s.end())` 反轉字串。(10931)
- `map<string, int>` 拿來做字串計數/分組,而且 **iterate `map` 出來的順序天生就是 key 的字典序**,不用額外排序就是照順序印出來。(10420 侵略紀錄, 10226 樹種統計都是靠這個特性直接印出排好序的結果)

## 數論與位元運算

- ⭐ **質數判斷**:`for(i=2; i*i<=N; ++i)`,只需要檢查到 `sqrt(N)`,不用整個掃到 N。(10235)
- **反轉整數**:`while(N){ n = 10*n + N%10; N/=10; }`。(10235 emirp:判斷一個數字反過來也是質數,而且原數不能是回文)
- **GCD 遞迴(歐幾里得算法)**:`GCD(i,j){ if(j==0) return i; return GCD(j, i%j); }`,一行就能背起來,很多數論題會用到。(11417)
- **數字反覆相加直到剩一位數(數字根,digital root)**:`while(n>=10) n = sum_digits(n)`。(11332)
- **9 的倍數規則**:一個數是 9 的倍數 ⟺ 各位數字和是 9 的倍數,可以拿來快速判斷/化簡。(10922,這題還進一步問「要加幾次才會變成剛好 9」)
- **11 的倍數規則**:各位數字「交替加減」(從某一端開始 +、-、+、-...),結果是 11 的倍數就代表原數是。(10929,注意這招對付「數字位數很長、超過 long long 存不下」的大數字特別好用,因為不用把整個數字轉成 int)
- **位元運算**:`n & 1` 判斷奇偶(等於 `n%2`),`n >>= 1` 等於 `n /= 2` 但更快;`__builtin_popcount(x)` 直接算一個數二進位裡 1 的個數,不用自己迴圈數。(10931, 10019)
- **逐位相加模拟進位**:拆兩數的每一位分別相加、記錄 `carry`,這是模拟直式加法的標準寫法,很多「進位次數/借位次數」題都是這個骨架。(10035)
- **sqrt 的浮點誤差要修正**:`int start = sqrt(a)` 這樣轉型截斷後,`start*start` 可能因為浮點誤差比 `a` 小一點點,所以要多判斷 `if(start*start < a) ++start;` 才保險,不要直接信任 `sqrt()` 轉 int 的結果。(11461,這是很經典的 WA 陷阱)

## 排序與資料結構技巧

- ⭐ **自訂排序規則**:寫一個 `bool cmp(a, b)` 函式傳給 `sort(v.begin(), v.end(), cmp)`,先比第一個條件,不相等才比第二個條件,一路比下去。(10008 字母出現次數由大到小、次數相同按字母排;11321 多重條件排序:先比 `%M` 的餘數,餘數相同看奇偶,奇偶也相同看奇數要遞減、偶數要遞增——這題是這 36 題裡排序規則最複雜的一題,考前值得重看)
- **中位數不用整個排序**:`nth_element(v.begin(), v.begin()+k, v.end())`,把第 k 小的元素排到正確位置,前面都比它小、後面都比它大,但兩邊內部不保證排序——只需要中位數本身時比完整 `sort()` 快。(10041,求每個點到中位數的距離總和)
- **氣泡排序 + 數交換次數**:排序過程中每交換一次就 `++count`,可以順便判斷「已經排好就提早跳出」(`swapped` flag)。(299)

## 模擬 / 2D 網格

- **矩陣旋轉列印**:先把每一行讀進 `vector<string>`,輸出時外層跑「直的位置」(column index)、內層倒著跑「原本第幾行」,就能做出把文字轉 90 度的效果。(490 Rotating Sentences)
- **掃雷模式(8 方向模擬)**:`dx[8]/dy[8]` 方向陣列存 8 個方向的偏移量,對每個地雷去「通知」周圍 8 格 +1(而不是對每格去數周圍有幾個雷),邊界檢查寫成 `nx>=0 && nx<n && ny>=0 && ny<m`。這個「方向陣列 + 邊界檢查」的骨架幾乎所有 2D 網格模擬題都用得到。(10189)

## 進位制 / 大數字轉文字(進階)

- **遞迴印出帶單位的數字念法**:例如印出「3 kuti 2 lakh...」這種每隔幾位數就有個單位詞的數字,用遞迴 + 一組 `divs[]`(每個單位對應的除數)和 `units[]`(單位字串)配對處理,從最大單位開始,`n >= divs[i]` 就先遞迴處理商數、印單位、再對餘數繼續處理下一個單位。(10101 Bangla Numbers)
- **輸出對齊**:`setw(4) << caseNum` 設定欄寬,配合前導的題號格式很常用。(10101)
- **Zeckendorf 定理(貪心表示成費氏數之和)**:任何正整數都能表示成不相鄰的費氏數相加,從最大且不超過 n 的費氏數開始貪心扣減,能扣就扣、標記 1,扣不了標記 0。(948 Fibonaccimal Base)
- **星期幾計算(Doomsday 系的日期題)**:硬記一個錨點對照表(例如某年 1/1 是星期幾),累加當月之前每個月的天數,對 7 取餘數對應到星期表;訣竅是把星期陣列的起始 index 設計成跟餘數直接對應,不用額外 if-else 校正。要小心閏年的月份天數表跟平年不一樣,若題目有跨年份要另外判斷。(12019)

## 幾何(進階)

- **弧長與弦長**:弧長 = `半徑 × 弧度`,弦長 = `2 × 半徑 × sin(弧度/2)`,角度要先轉弧度(`角度 × π/180`)才能丟進三角函式。若題目給的角可能超過平角,通常要先轉成「劣角」(`if(a>180) a = 360-a`)。(10221 Satellites)

## 精度與常見雷區(丟分/送分的關鍵)

- ⭐ `pow()` 是浮點數函式,次方大的時候結果轉 `int` 可能會因為浮點誤差差 1,能用「迴圈自己累乘」取代就不要用 `pow()`。(10268 修過這個雷)
- ⭐ 除以 0 要先判斷,不要讓分母變成 0 才發現。(10056 機率題:`if(p==0.0) return 0`)
- ⭐ 多筆測資的終止條件如果是「兩個變數都是 0」,要寫 `(a!=0 || b!=0)`,不是 `&&`——只要任一個不是 0 就還要繼續處理。(10035, 11461, 11321 都用這個寫法)
- 輸出格式細節:單複數字尾(`carry operation` vs `carry operations`)、每組測資之間要不要空行、`Case i:` 這種編號要不要冒號——這些幾乎不影響邏輯對不對,但寫錯就是 WA,交題前要對照範例輸出逐字檢查。(10035, 10783 `Case i:`, 10189 field 之間的空行)
